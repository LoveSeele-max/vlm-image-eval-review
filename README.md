## 打开接口配置

在 Windows 中双击根目录的 `配置接口.cmd`，填写地址、模型名和密钥，再点击“保存并测试连接”。需要带 Tkinter 的 Python 3，无额外包依赖。

文字测试成功后，点击“多图＋JSON 测试”。窗口会自动生成三张彩色图形，显示预览，并核对 JSON 字段、图片顺序、颜色、形状及数量，不需要选择正式评测图片。

地址和模型名会保存到被 Git 忽略的本机配置；密钥仅在本次窗口会话中使用。两类测试分别保存私有摘要，每次点击发送一次请求，可能产生接口费用。详见 [使用说明](./接口配置使用说明.md)。

## 打开人工标注页

双击根目录 `启动人工标注.cmd`，打开本机 `http://127.0.0.1:8501`。需要 Python 3 与 `image-eval-review/requirements.txt` 中的 Pillow。默认显示三张联调图，标注人为“水水”；点击图片放大，逐项填写后点击“保存本项”。

62 项已有记录已导入，判断未变。保存后可关闭浏览器，下次继续；未填写判断的条目可保存草稿。全部填写完成后，由作者点击“确认本图初始记录”，此后修改须填写原因并保留原快照。数据库仅保存在本机私有目录，此页面操作不调用 API。详见 [D01 使用与验证说明](./D01_匿名人工标注页.md)。

## 生成正式评测请求

在项目根目录运行：

```powershell
python image-eval-review/judge_client.py --sample-id sample_020
```

默认只在 `image-eval-review/private/judge_runs/` 生成三图请求文件，不联网、不需要密钥。使用现有配置窗口保存的地址与模型名，环境变量可覆盖。显式添加 `--send` 后委托 D03 建立单任务批次，在上限内有限重试或复用成功结果，并要求开发集样本已由作者确认初始快照；密钥仅从 `VLM_API_KEY` 读取。D02/D03 实现时没有调用中转，D04 已完成三条真实发送验收。详见 [D02 使用与验证说明](./D02_正式调用与严格校验.md)。

## 运行记录与恢复

三张初标确认后，可双击根目录的 `启动三图联调.cmd`，在密码框填写本次会话的 Key，点击“开始运行”。窗口会核验输入并复用已有三图批次，通过下述 D03 执行器运行；密钥不写入文件。详见 [D04 记录](./D04_三图联调记录.md)。

查看本机运行库：

```powershell
python image-eval-review/run_tasks.py status
```

创建批次只准备本地输入和任务，不发送：

```powershell
python image-eval-review/run_tasks.py create --sample-id sample_020 --sample-id sample_029 --sample-id sample_042
```

将返回的批次编号用于 `run --batch-id ...` 或 `resume --batch-id ...`，二者均可能发送请求；`recover --batch-id ...` 仅整理中断记录。三个入口共用工作进程锁，避免活跃任务被另一个进程恢复。相同成功结果经证据核验后复用；每任务默认最多 3 次尝试，配置错误停止批次，重试历史保留。

本机三图批次已在 D04 真实运行通过，编号见 `image-eval-review/private/d03_created_batch.json`。结果报告为 `image-eval-review/private/reports/D04_三图结果报告.md`，含 62 项模型判断和人工初始状态对照；原始证据位于 `image-eval-review/private/runs/evidence/`。模型运行库为 `image-eval-review/private/runs.sqlite3`，与人工标注库分开。详见 [D03 命令与验证记录](./D03_运行记录与恢复.md)和 [D04 实际验收](./D04_三图联调记录.md)。

## 提交约定

每完成一个编号任务（A01–H04），完成必要核验、更新任务记录和证据后，单独创建一次 Git commit。提交信息包含任务编号，例如：

```text

docs(A02): 固定参考照片并记录选择依据
feat(D02): 实现多图调用与结构化校验
```

首次提交收录现有方案、任务记录和 A01 素材索引。未完成任务不提前勾选；后续修复可单独使用 `fix(任务编号)`，保留真实历史。
