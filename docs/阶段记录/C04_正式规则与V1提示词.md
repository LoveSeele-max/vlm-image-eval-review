## 参考图可判性核查

使用固定的两张原始照片，先核对原图 SHA-256，再整图缩放为 **1536×2048** 的 RGB PNG。Codex 查看实际生成的整图输入，未单独裁切局部送评，未查看候选图结果。

| 重点 | 本地所见 | 规则处理 |
| --- | --- | --- |
| 眼下疤痕样标记 | 主参考画面右侧眼外下方，深色线及横向短划可辨，与眼轮廓和旁边白色图案可区分 | 保留必需项；候选按面部对应关系核对，不能机械要求始终位于画面右侧 |
| 内耳分区 | 主参考两根长耳内部深棕色区域与浅色外围可区分；补充参考主要展示耳背 | 保留必需项，不能从耳背推定内耳状态 |
| 背部草帽 | 补充参考可辨帽檐、帽冠、纹理及红帽带；主参考只展示部分帽缘 | 保留辅助项，候选角度不足时记录不可判断 |
| 双长耳与其余外观 | 耳尖完整，发束、红衣、蓝色短裤及金色圆形钱币样底座均可辨 | 维持原定义，外侧白色转盘不计入底座 |

详情见 [参考可判性记录](../../image-eval-review/data/reference_readability.json) 与 [本地图片处理回执](../../image-eval-review/data/reference_inputs.check.json)。

本地核查说明参考有可用视觉依据，不保证每张 512×512 候选都露出这些细节，也不证明中转服务或模型能识别。看不清仍使用 `unjudgeable`。本次是 Codex 本地检查，不是用户对候选的人工初标，也不是正式视觉 API 评测。

## 固定图片输入约定

| 项目 | 约定 |
| --- | --- |
| 顺序 | 图 1：REF-MAIN；图 2：REF-SUPPLEMENT；图 3：唯一候选 |
| 参考尺寸 | 整图保持比例，长边最多 2048；当前两图均为 1536×2048 |
| 候选尺寸 | 整图长边最多 512；当前候选原生 512×512，不放大 |
| 处理 | EXIF 方向校正、RGB、LANCZOS 缩小、PNG 编码；无裁切、无放大 |
| 接口 detail | 正式请求计划使用 `high`，其支持与处理效果待 D04 核对，不静默改用基础测试的 `low` |
| 人工显示 | 使用同一预处理整图，可以缩放查看；不为模型额外补发局部图 |
| 记录 | 原图与处理后图片哈希、尺寸、Pillow 版本；D03/D04 还须记录实际请求参数 |

预处理函数见 [prepare_image.py](../../image-eval-review/prepare_image.py)，约定见 [image_input_policy.json](../../image-eval-review/data/image_input_policy.json)。当前回执使用 Pillow 12.2.0；不同环境重新编码可能改变字节，应记录实际版本和输出哈希，不能声称与冻结回执完全一致而不核对。

## 第一版评测提示词

全文见 [judge_v1.txt](../../image-eval-review/prompts/judge_v1.txt)。它固定三图顺序、三个可用视觉标签、证据格式、木桌排除及完整返回要求；不让模型决定整体状态。

模板只有两个占位符：规则版本和当前样本上下文。`freeze_rules.render_prompt(sample_id)` 使用正式规则生成上下文，包括原始提示词、固定参考说明、共同边界，以及该样本应检查的完整条目；不传来源路径、文件名、seed 或 LoRA 配置。

本地查看一条样本的完整提示词，可以在仓库根目录运行：

```powershell
python -c "import sys; sys.path.insert(0, 'image-eval-review'); from freeze_rules import render_prompt; print(render_prompt('sample_020'))"
```

这条命令只打印文字，不调用 API。后续 D02 将按固定顺序附上图片，保存实际发出的提示词、Schema 和版本。V1 已含共同规则及全部判定边界；V2 只能改善表达、补充解释和示例，不更换标准、条目、必需性、输入图片或结果字段。
