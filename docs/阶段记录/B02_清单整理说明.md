## 文件与字段分工

| 文件 | 用途 |
| --- | --- |
| [manifest.draft.jsonl](../../image-eval-review/data/manifest.draft.jsonl) | 48 条候选草稿：匿名编号、候选资产编号/哈希/尺寸、参考编号、原始提示词、要求及待处理状态 |
| [sample_sources.jsonl](../../image-eval-review/data/sample_sources.jsonl) | 内部映射：来源路径、文件名、批次、base/LoRA、seed、证据、暂定条件组和重复候选关系 |
| [reference_assets.json](../../image-eval-review/data/reference_assets.json) | 两张固定参考图的资产编号、路径、哈希与尺寸 |
| [prompt_requirements.json](../../image-eval-review/data/prompt_requirements.json) | 5 份提示词模板、别名与要求目录；明确标记为规则冻结前的草稿 |
| [generation_config.json](../../image-eval-review/data/generation_config.json) | 历史命令中的公共生成参数；运行时版本、scheduler、权重哈希等未核实值保留为 `null` |
| [manifest.build.json](../../image-eval-review/data/manifest.build.json) | 样本数、要求条数分布、输入文件哈希和阶段状态 |

草稿只保存 `candidate_asset_id`、`reference_ids`，不把原文件路径混进标注数据。后续工具按匿名编号到内部映射中解析实际路径。这里的“内部”表示不进入人工初标视图，不表示文件已加密或对仓库读者保密。

后续 D01 使用 [build_manifest.py](../../image-eval-review/build_manifest.py) 中的 `annotation_view()` 白名单，仅取匿名编号、候选/参考资产编号、原始提示词与要求。路径、原文件名、模型配置、条件组、哈希和 AI 结果均不在该视图中。当前只实现数据分离与投影函数，尚未实现标注页面或图片服务。

作者见过历史图片，且原始提示词本身能反映提示词差异，因此只称为减少配置提示的匿名标注，不称为严格盲评。

## 提示词要求如何摘录

| 原文来源 | 候选数 | 每条要求数 | 摘录范围 |
| --- | ---: | ---: | --- |
| P0 | 8 | 3 | 照片风格、手办、木桌 |
| P1 | 8 | 3 | 同上；保留 zqv 原文，不将触发词直接变成可见属性 |
| P2 / D1_original | 16 | 12 | 上述场景与玩具外观，以及头发、长耳、肤色、眼睛、服装、鞋和底座 |
| D2_explicit_ears | 8 | 14 | 细化兔耳位置、深色内耳及其与脸侧小圆耳的区别 |
| TRIGGER_ORIGINAL | 8 | 2 | 照片风格、手办；不追加木桌、服装或耳部要求 |

例如 `sample_002` 的原文为 `a photo of a figurine on a wooden table`，只摘录 3 项要求：

```json
{
  "sample_id": "sample_002",
  "requirements": [
    {"id": "photo_style", "description": "以照片风格呈现。", "source_quote": "a photo"},
    {"id": "figurine", "description": "画面中有手办。", "source_quote": "figurine"},
    {"id": "wooden_table", "description": "手办放置在木桌上。", "source_quote": "on a wooden table"}
  ],
  "group_id": null,
  "split": null,
  "selection_status": "pending_B03"
}
```

没有把参考照片中的草帽或方案示例中的白色背景追加到提示词要求中。主体关键特征由 C01 单独定义，不能与“提示词明确要求了什么”混为一谈。C02-C04 冻结判定规则；若后来修改样本要求摘录，须登记新的清单版本，不能悄改已冻结数据。

## 验证与复现

在仓库根目录运行：

```powershell
python image-eval-review/build_manifest.py
python -m unittest discover -s image-eval-review/tests -p test_build_manifest.py -v
```

生成脚本会先重新核验 B01 的原图哈希。若输入集合变化、原图改变、提示词别名不符、要求引文不在原文中，或已经存在后续正式清单/划分，会拒绝重建。清单生成只依赖 Python 标准库；原图仍由路径引用，克隆仓库不会获得图片。

新增 10 项测试全部通过，覆盖来源与检查证据对应、编号稳定性、配置隔离、提示词要求边界、重复候选保留、错误输入拒收和后续冻结文件保护。两次连续重建得到的 4 份生成文件逐字节一致。

`manifest.build.json` 的输入文本哈希统一按 UTF-8、LF 换行计算，避免 Windows/Git 换行转换改变证据；图片 SHA-256 始终按原始字节计算。
